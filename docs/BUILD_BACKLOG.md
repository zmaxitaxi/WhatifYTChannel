# Remaining release build

Updated October 31, 2026, after the degree-expiry review and the verified continuous
Stanford-in-Boston rebuild. This separates working MVP capabilities from the
broader release targets in [TECHNICAL_PLAN.md](../TECHNICAL_PLAN.md).

## Working local MVP

- Validated production/evidence contracts and generated schema/types.
- Deterministic Three.js rendering, readable caption layout, frame sampling,
  lossless capture chunks, cancellation and resume.
- Local queue/review website, progress, claims/sources, and MP4 export.
- Original sound library, music/effect mixing, H.264/AAC delivery and independent
  format/loudness inspection.
- ChatGPT-authenticated Codex planning with a fixed supported template and up to
  two structural repairs; the creative guide is included and hashed.
- Stanford relocation/alternate-history examples and the connected degree-expiry
  world. The new connected Boston waterfront is another authored world, not
  evidence that arbitrary new topics already generate without development.
- A shared continuous renderer for timeline, serif captions, camera interpolation,
  optional meaningful counters, and story-specific lighting. The permanent Astra
  modeling chat supplies world/action work while the parent integrates it.

## 1. Make the next topics reusable

The largest gap: current worlds and camera choreography still need per-story
development. Build approved, configurable scene modules and a capability/asset
registry so a structured plan can compose a new continuous journey from existing
campuses, interiors, paths, props, people, transport, and transformations.

Acceptance: produce additional held-out topics from specifications without editing
per-video animation code. Keep no cuts, the persistent checkpoint timeline, and
fitting continuous music; vary routes and tone, including hopeful futures.

## 2. Complete the original scenario coverage

Add and integrate the remaining families: swaps, disappearance/absence, public or
private status changes, rankings, fictional territories, mergers, crowd flows,
and symbolic competition. Create recognizable Berkeley, Harvard, MIT, UCLA and
simplified Ivy League identity kits and their allowed layouts. An enum or a
standalone package is not a completed supported scenario.

Acceptance: every original concept has a complete diagnostic run and each
scenario family has a passing final example under the current visual direction.

## 3. Connect research, story planning, and evidence

Francis's research/content packages are available but are not yet automatically
orchestrated into the production loop. Wire topic → source-backed fact pack →
causal script → supported journey plan. Expand evidence and metric bindings so
dates, counts, assumptions, and fictional outcomes remain inspectable and useful.

Acceptance: a fresh supported topic uses retrieved evidence and explicit
assumptions rather than inheriting a hard-coded fixture's facts and world.

## 4. Close the visual review and revision loop

Current format checks, caption fitting, deterministic-seeking tests, and delivery
inspection do not replace story/action review. Add model framing/clearance and
story-correspondence evaluation, image/motion critique, and bounded repairs based
on the rendered result. The website currently records revision notes and rejects
the old draft; it does not generate the requested revision automatically.

Acceptance: a failed visual/content check leads to an inspectable repair within
the agreed budget, followed by a verified rerender. Human approval remains manual.

## 5. Run release reliability and quality trials

Run the twelve original concepts plus six held-out variations. The original gate
requires at least 16/18 reviewable completions, a passing example per scenario
family, three consecutive unattended jobs, no per-video code edits, and no
unresolved factual/fiction labeling errors. Test recoverable cancellation,
authentication/usage interruption, and restart across that trial.

Collect human rubric scores: average at least 4/5, with no dimension below 3.
Benchmark the designated machine against the planned 30-minute render target for
a 60-second video and median 60-minute end-to-end target. Individual successful
exports do not establish the full release gate.

## 6. Integrate discovery, analytics, then production scheduling

Connect the existing discovery/analytics packages to candidate selection,
deduplication, review history, and measured audience feedback. After quality and
reliability gates pass, implement the planned single daily production opportunity,
two-item review cap, local-date deduplication and no catch-up backlog. Scheduling
is not active. Publishing remains human-controlled; automatic YouTube publishing
is outside the release scope.

Recommended next build: finish the reusable journey modules and prove them on two
new topics, while wiring research/planning to those same supported modules.
